# Cyber Security 101 — Offensive Security Intro

## Purpose

Offensive security uses authorised adversarial testing to discover weaknesses in systems, applications, and networks. The objective is to help organisations understand and reduce exposure before a real attacker exploits it.

## Typical phases

1. **Scoping and authorisation:** Define permitted targets, methods, time window, and reporting requirements.
2. **Reconnaissance:** Collect information relevant to the authorised target.
3. **Enumeration and validation:** Identify exposed services and potential weaknesses.
4. **Controlled testing:** Validate findings without exceeding the agreed scope.
5. **Reporting:** Explain evidence, impact, likelihood, and remediation.

The exact methodology varies by engagement. Testing should avoid unnecessary disruption and protect any sensitive data encountered.

## Common concepts

- **Attack surface:** The set of points where a system can be interacted with or attacked.
- **Vulnerability:** A weakness that may be exploitable.
- **Exploit:** A technique or code that uses a weakness.
- **Proof of concept:** A limited demonstration that helps validate a finding.
- **Remediation:** A change that reduces or removes the risk.

## Security relevance to defenders

Understanding offensive methods helps defenders anticipate reconnaissance, prioritise exposures, and interpret alerts. Defensive teams should use threat-informed testing results to improve detection and controls.

## Key takeaways

- Permission and scope come before testing.
- Findings need evidence and clear impact statements.
- A suspected vulnerability should be validated safely.
- Reports should give practical remediation guidance.
